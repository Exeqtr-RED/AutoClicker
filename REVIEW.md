# Ревизия кода + фича «Поделиться пресетами»

Дата: 2026-11-05 · Версия проекта: 2.8 (versionCode 18)

## 1. Фича: возможность делиться пресетами

### Как это работает

**Отправка (экспорт):**
- В редакторе пресета (ST/MTWS) **долгий тап по пресету** открывает меню
  «Поделиться / Удалить» (раньше долгий тап сразу удалял — случайно
  потерять пресет было проще, чем отправить другу).
- «Поделиться» пишет пресет в файл `<имя>.sekira.json` (кеш приложения)
  и открывает системный шэринг через FileProvider (`content://`) —
  Telegram, WhatsApp, почта, облако, «Сохранить на диск» и т.д.

**Приём (импорт) — четыре сценария:**
1. Мессенджер → «Поделиться → Sekira Cliker» (ACTION_SEND, файл или текст).
2. Файловый менеджер → «Открыть с помощью → Sekira Cliker» (ACTION_VIEW).
3. Редактор → кнопка **«Импорт пресетов (файл .sekira.json)»** (SAF-пикер).
4. Пересланный JSON-текст — тоже принимается (парсер отрезает мусор
   вокруг JSON: BOM, подпись мессенджера и т.п.).

При импорте приложение показывает список найденных пресетов и после
подтверждения добавляет их. **Совпадения по (имя, режим) не затираются** —
новый пресет получает суффикс «(2)», «(3)»…

### Формат файла

```json
{"format":"sekira-preset","version":1,"exportedAt":1699999999999,
 "app":"Sekira Cliker","presets":[ { …Preset.toJson()… } ]}
```

Парсер терпимый: принимает обёртку, голый массив, одиночный объект.

### Защита импорта (данные из недоверенного источника)

- пресет с **пустыми actions отбраковывается целиком** — иначе ST-пресет
  без тапа при playback кликал бы по дефолтной точке крестика (140, 540)
  (тот самый баг v42/S3, через импорт он не должен возвращаться);
- `mode` нормализуется: MTWS остаётся MTWS, всё прочее → ST;
- `timingMode` нормализуется в {INFINITE, DURATION, CYCLES};
- числовые поля прижаты к потолкам редактора (задержка/периодичность ≤
  сутки, разброс ≤ минута, `cycles ≥ 1`);
- действия с неизвестным типом пропускаются;
- битые элементы пропускаются, файл-мусор не роняет приложение.

## 2. Найденные ошибки (исправлены в этой ветке)

### BUG-1 (средний, потеря/порча данных): черновик редактора перезаписывался «чужим» режимом
`SettingsActivity.onNewIntent` при смене режима (ST↔MTWS из плавающей
панели) вызывал `recreate()`. Старый экземпляр проходил `onDestroy` с
`isFinishing == false` → `writeDraft()`, но поля формы ещё содержали
данные **старого** режима, а `draftKey()` строился от **нового** —
ST-черновик записывался в ключ `draft_MTWS` (и наоборот). При следующем
«свежем» открытии редактора другого режима `restoreDraft()` показывал
чужие поля. **Фикс:** флаг `pendingModeSwap` — при recreate() после смены
режима черновик не перезаписывается.

### BUG-2 (низкий, потокобезопасность): read-modify-write без блокировки в PresetStorage
`save()`/`delete()` делают read-modify-write через `getAll()`, а кэш —
check-then-act. Все вызывающие в приложении — главный поток, но
импорт пресетов может быть вызван из колбэков, androidTest — из
тестового потока. **Фикс:** `@Synchronized` на `getAll`/`getByMode`/
`save`/`delete` (дешёвая блокировка, инвариант «кэш == хранилище»).

### BUG-3 (тестовая инфраструктура): юнит-тесты не могли выполняться
`PresetTest` использует `org.json`, но в android.jar для локальных
unit-тестов это заглушки «Stub!» → RuntimeException. **Фикс:**
`testImplementation("org.json:json:20240303")`. Теперь весь блок
(26 тестов) реально выполняется и зелёный.

## 3. Утечки памяти — проверка

Утечек **не найдено**. Прошлые фиксы в коде уже закрывают типовые
источники (все проверены в этой ревизии):

- колбэки службы → `WeakReference` + обнуление в `onDestroy` и при отказе
  службы (`pendingPickCb`/`pendingRecordCb`/`pendingInsertCb`);
- `recheckHandler`/`recheckRunnable` в MainActivity — `removeCallbacks`
  в `onPause`/`onDestroy`;
- фоновый поток Updater — только `WeakReference` на Activity, guard
  `isAlive()` перед каждым UI-вызовом;
- окна оверлеев — полный tear-down в `onDestroy` службы (10 окон
  перечислены), `pendingMarkerLongPresses` снимается при удалении маркеров;
- `uiTicker`/`tick` — `removeCallbacks` на стопе и рестарте;
- анимация клика — `animate().cancel()` перед `removeView`;
- `lastRecordResult`/`lastPickResult` — потребляются через consume-методы,
  перезаписываются при следующем старте (потолок 5000 действий ≈ 250 КБ,
  фиксированный).

Нишевое накопление возможно только в двух предельно редких случаях
(не исправлял — риск/сложность не оправданы):
- backup-ключи `list_corrupted_<ts>` в SharedPreferences копятся при
  КАЖДОЙ неудаче парсинга (но это и задумано: резерв для восстановления);
- `dialog` неявно удерживается, если показан в момент destroy —
  стандартное поведение Android, не утечка уровня Activity.

## 4. Оптимизация — оценку производительности

Код уже плотно оптимизирован в прошлых версиях (кэш распарсенных
пресетов, кеш Vibrator, кеш TextView номеров маркеров, in-place refresh
маркеров, event-driven ожидание жестов вместо busy-poll 20 мс,
тикер 1 Гц с дедупликацией setText, commit/apply по частоте вызова).
Новой оптимизации не требуется; в share-ветке:

- экспорт — разовая операция по явному тапу (JSON ~КБ, ноль влияния);
- импорт — синхронное чтение файла в UI-потоке допустимо (диалог
  подтверждения идёт после разбора; файлы пресетов — килобайты);
- `uniqueName` — один проход по кэшу PresetStorage (O(n), n — число пресетов);
- `share()` чистит кеш-каталог перед записью — копится максимум один файл.

## 5. Замечания, требующие решения владельца (не исправлял)

1. **Updater никогда не найдёт обновление**: `versionName = "2.8"`,
   а теги релизов вида `v0.35_AlfaTest` — `compareVersions("2.8", "v0.35")`
   → «тег старше». Нужна согласованность нумерации релизов (или
   сравнение по versionCode).
2. `onSaveInstanceState` пакует до 5000 действий (~500 КБ JSON) в Bundle —
   у крайних пользователей может ловить `TransactionTooLargeException`.
   Лечится хранением черновика только в SharedPreferences.
3. `Intent.EXTRA_TEXT` в фильтре SEND делает приложение видимым в
   шэринг-листе для любого текста; нерелевантные шары тихо игнорируются,
   но в списке Sekira Cliker появляться будет. Если шумит — уберите
   `text/plain` из SEND-фильтра (файловый импорт остаётся).
